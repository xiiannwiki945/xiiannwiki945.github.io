用 Hugo + GitHub Pages 搭一个完全属于自己的博客

2026-11-14 · 3 分钟 · #Hugo #GitHub Pages #静态博客

这个站点就是按下面的方式搭起来的。整套东西没有数据库，没有后台，没有需要续费的服务，唯一的依赖是 GitHub 的免费静态托管。

为什么是静态站

动态博客（WordPress 那类）的每一页都是临时拼出来的：请求进来，PHP/Node 查数据库，渲染模板，返回 HTML。静态站把这步提前到推送的时候——写作时是一次编译，之后每个访客拿到的都是同一个 HTML 文件。

区别不只是"快"：

  • 访客碰不到你的代码执行环境，也就没有注入、爆破后台这类问题
  • 页面可以直接丢给任何 CDN，缓存命中率接近 100%
  • 文章的源文件是 .md，不是数据库里的一行记录，随时可以打包带走

代价是：没有原生评论、没有登录、没有站内搜索后端。这些都能用第三方或纯前端方案补上，后面会说。

三个框架怎么选

框架运行时构建速度部署到 Pages
JekyllRuby中原生支持，push 即构建
HexoNode.js中需要 Action 或 deploy 脚本
HugoGo（单二进制）极快需要 Action，配置简单

几百篇文章在 Hugo 这里是"秒级"的量级，而且它只有一个可执行文件，不依赖 Ruby/Node 环境，在 ARM 小主机上装完就能用。对长期写作的人来说，构建时间和环境依赖是最容易被低估的成本。

选型建议
如果你已经有 Node 环境、喜欢折腾主题，Hexo 的生态更热闹；如果你只想写东西、不想维护环境，Hugo 更省心。Jekyll 的优势只剩 GitHub 原生构建，但它的插件白名单会限制你，实际用起来反而别扭。

几个容易踩的坑

baseURL 写错：这是 404 和样式丢失的头号原因。仓库名必须是 <用户名>.github.io 才能用根路径；如果叫 blog，地址就是 https://<用户名>.github.io/blog/，baseURL 也必须带上这个子路径。

大小写：主题里的大小写不敏感路径在某些系统上能跑，推上去就 404。文件名一律小写最省事。

直接拷主题的 exampleSite 配置：里面的语言、菜单、示例内容会一起带进来，构建出来的首页常常不是你想要的。

submodule 引主题：Actions 里必须加 submodules: true，否则构建出来的页面没有样式。
