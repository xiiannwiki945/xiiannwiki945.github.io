日常写作流程：从 hugo new 到 git push

2026-11-12 · 3 分钟 · #Hugo #工作流

把写作拆成四个动作：新建、写、本地预览、推送。熟悉之后，一篇文章从动笔到上线不超过五分钟的操作成本。

新建：一条命令带好骨架

生成的文件顶部是 front matter，四五个字段就够用：

date 和 draft 值得单独说：本地预览默认不显示草稿，只有加了 -D 才看得到；而站点构建时又只看 draft 和日期是否在未来。所以"先挂着、以后再说"的成本很低，不会被迫在半成品状态推送。

写：Markdown 只用到六种语法

标题、列表、引用、代码块、链接、加粗。这六种能表达的东西已经够写技术笔记了，剩下的语法大概一年也用不上一次。

一个经验：先把话说完整，再回头调格式。排版是最容易变成拖延借口的环节，写着写着就开始调行距和字体，文章本身反而没推进。

本地预览：实时刷新比想象中重要

保存即刷新，而且 --navigateToChanged 会把浏览器停在你正在改的那一段，光标位置也保留。写长文的时候，这一个参数省掉的是几百次滚动。

预览用的地址是 localhost:1313，和线上环境同源同模板，只是没有 CDN 缓存。样式上的问题在这里基本都能发现。

推送：两条命令，等三十秒

推送之后 Actions 开始构建，一般半分钟到一分钟。这段时间不用盯着，写完一篇就开始写下一篇，回头看构建结果就行。

一个小习惯
提交信息统一用 post: 标题 / fix: 说明 两类前缀。半年后回头看历史，几乎不用点开就知道每次改了什么。

几个让流程更顺的细节

  • 图片统一放在 static/images/，文件名带日期，比如 20261108-monitor.png
  • 一篇文章只解决一个问题，标题里就能看出它解决什么
  • 草稿态用 draft: true 挂着，不删也不推，想接着写随时回来
  • 每周翻一次草稿目录，写不下去的直接删掉，不留负担
