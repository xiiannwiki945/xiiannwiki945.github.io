把内容存成文件：静态博客和自托管监控的同一个思路

2026-11-08 · 3 分钟 · #随笔 #自托管

前面写过家里那套监控：摄像头把录像写到本地硬盘，不做云存储，需要的时候再调出来看。搭这个博客的时候我发现，两者是同一种思路的两种表现。

共同点一：原始数据是文件

监控系统的核心不是那个查看界面，而是硬盘上的 .mp4。界面坏了、软件停更了，录像还在，换个播放器照样能看。

博客的核心也不是主题和框架，而是 content/ 里那些 .md。Hugo 哪天不维护了，换成 Hexo、Eleventy 甚至自己写个脚本，正文一个字都不会丢。

反过来说，如果文章只存在于某个平台的编辑器里，你拥有的其实是"访问权"，不是"所有权"。平台改规则、加广告、限制导出、甚至关停，你只能接受。

共同点二：构建和运行分离

监控是"采集 → 落盘 → 回放"三段，博客是"写作 → 编译 → 托管"三段。中间那步都是把原始数据变成可直接消费的成品：

监控博客
原始数据摄像头视频流Markdown 源文件
加工编码、切片、索引Hugo 编译成 HTML
成品硬盘上的录像文件public/ 静态目录

这种结构的好处是：原始数据永远比工具活得久。换掉回放器不影响录像，换掉主题和生成器也不影响正文。

反过来，如果把两步合成一步——边录边编码成私有格式、边写边存进数据库——那个中间产物就变成了新的依赖。工具一换，数据就跟着废掉一半。

共同点三：不依赖单一厂商

录像换个播放器还能看，博客换托管也一样：GitHub Pages → Cloudflare Pages / Netlify / 一台 VPS 上的 nginx，改一下 DNS 就行。域名在自己手里，就还有退路。

这一点的价值不在"搬家"本身，而在于你知道自己能搬。有退路的时候，选择反而是轻松的——不用因为"搬不动"而忍下一个越来越难用的平台。

代价也要说清楚

没有后台、没有原生评论、没有统计面板，这些都得自己补。硬盘会坏，所以要有备份，而且得定期确认备份是能恢复的，不是只存在过。博客的搜索只能在前端做一份索引，文章多了索引文件也会变大。

说白了，成本从"每月订阅费加平台规则"换成了"一次性搭建加偶尔维护"。前者是持续的、被动的；后者是集中的、自己可控的。哪种更划算，取决于你打算写多久。

最后

把内容存成文件，不是为了复古。它换来的是一条确定的边界：这部分东西永远是我的，工具只是工具。
